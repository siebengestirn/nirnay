# M3.6.0 — fail-closed authority startup — 2026-11-21

Dated evidence for the narrow safety prerequisite. Synthetic fixtures only;
no provider data, broker access or live order submission.

## Defect

`AuthorityState::default()` started with `session_open: true`,
`account_snapshot_available: true`, `kill_switch_engaged: false` and
`reconciliation_blocked: false`. A newly constructed `RiskAuthority` therefore
appeared ready without any startup evidence, and a caller could reserve risk
immediately. The readiness setters also bumped the account-state revision,
conflating operational control flags with economic state.

## Correction

- Default authority state is now unready: session closed, account snapshot
  unavailable, kill switch engaged, reconciliation blocked.
- Readiness setters no longer bump the account-state revision; they are control
  facts, not economic events. `set_session_open` already behaved this way.
- The synthetic paper runner now marks readiness explicitly from its run inputs
  and records in code that these are fixtures, not measured evidence. M3.6.1
  will replace them with typed, owned health observations enforced inside the
  authority.
- Tests: a fresh authority is rejected on `SessionOpen`,
  `AccountSnapshotAvailable`, `KillSwitch` and `Reconciliation`; the existing
  fixture supplies readiness explicitly before exercising other checks.

## Boundary

This is not the complete health-to-risk integration. It removes the
default-ready state only. It does not claim operational readiness, broker
correctness or real-source certification, and it does not authorize capture.
